================================================================================
                    Duris.sbs - Playable Races and Classes Guide
================================================================================

This document explains how to add, edit, or modify the playable races and
classes available during character creation. Both telnet and WebSocket clients
use the same data structures.

For the PC class catalogue, player help links, progression, specializations,
and multiclassing, see docs/reference/CLASSES.md.

================================================================================
                    QUICK OPERATOR CONFIGURATION
================================================================================

For normal enable/disable changes, edit:
  lib/creation_availability.cfg

The file is loaded at server boot, so restart the server after changing it.
Use true to show and allow an option; use false to hide it from the creation
menu and reject it if a client submits the option directly. Missing settings
default to enabled.

Examples:
  creation.class.dragoon.enabled=false
  creation.class.dragoon.enabled=true
  creation.race.kobold.enabled=false
  creation.race.kobold.enabled=true

Class names are normalized lowercase names. Race names use hyphens for spaces,
for example mountain-dwarf and grey-elf.

CREATION_ALL_CLASSES=TRUE in .env overrides both the per-class switches and
the race/class restrictions for character creation. Normally unavailable
choices are clearly labelled and selected by typing the full class name in the
telnet menu; WebSocket clients receive restricted/restricted_note fields. The
committed .env.example currently sets this override to FALSE.

The per-option config only affects new character creation. It does not change
existing characters, class/race mechanics, race/class alignment rules, or item
limits. While CREATION_ALL_CLASSES remains on, specialization race filtering
is also relaxed so direct-created combinations retain their class features.
Use the source tables described below only when adding a new class/race or
changing a race/class alignment combination.

================================================================================
                              PLAYABLE RACES
================================================================================

Location: src/core/constant.c (search for "playable_races")

The playable_races[] array defines which races players can choose during
character creation. Each entry has three fields:

    { RACE_ID, 'menu_key', "faction" }

Example:
    { RACE_HUMAN,      'h', "good" },
    { RACE_DROW,       'd', "evil" },
    { RACE_THRIKREEN,  'k', "neutral" },

Fields:
  - RACE_ID    : The race constant from defines.h (e.g., RACE_HUMAN, RACE_DROW)
  - menu_key   : The lowercase letter/number for telnet menu selection
                 Uppercase = show help, e.g., 'h' selects Human, 'H' shows help
                 For numbers: '1' selects, '!' shows help (shift key)
  - faction    : "good"    = Good creation-side group
                 "evil"    = Evil creation-side group
                 "neutral" = Player chooses good or evil during creation

Alignment is separate from racewar side. Telnet resolves fixed or selectable
alignment from the race/class cell. WebSocket assigns good/evil from this faction
field, or from a neutral-faction player's good/evil choice, then checks only fixed
good/evil class requirements. It does not resolve neutral and mixed alignment
cells in the same way. A legal matrix cell is not proof that both clients can
complete it; Human Necromancer, for example, is rejected by WebSocket's fixed-good
Human alignment even though its matrix cell permits evil.

--------------------------------------------------------------------------------
                         HOW TO ADD A NEW PLAYABLE RACE
--------------------------------------------------------------------------------

1. Open src/core/constant.c

2. Find the playable_races[] array by name

3. Add a new entry before the sentinel { -1, 0, NULL }:

   Example - Adding Wood Elf as a good race with 'w' key:

     { RACE_WOODELF,    'w', "good" },

4. Make sure the menu_key is unique (not used by another race)

5. Recompile the MUD:
   cd src && make

6. The race will now appear in both:
   - Telnet character creation menu
   - WebSocket chargen_options response

--------------------------------------------------------------------------------
                     HOW TO REMOVE A PLAYABLE RACE
--------------------------------------------------------------------------------

Preferred method: edit lib/creation_availability.cfg and set the race to false.
For example:

  creation.race.kobold.enabled=false

Restart the server. The race is removed from both the telnet and WebSocket
creation menus and direct submissions are rejected. Do not remove the entry
from playable_races[] unless permanently deleting the race from the codebase.

--------------------------------------------------------------------------------
                      HOW TO CHANGE A RACE'S FACTION
--------------------------------------------------------------------------------

1. Open src/core/constant.c

2. Find the race entry and change the faction string:

   Before: { RACE_MINOTAUR,   's', "neutral" },
   After:  { RACE_MINOTAUR,   's', "evil" },

3. Recompile: cd src && make

================================================================================
                              CLASS AVAILABILITY
================================================================================

Location: src/core/constant.c (search for "class_table")

The class_table[][] matrix determines which classes each race can play and
what alignment restrictions apply.

Format: class_table[RACE][CLASS] = alignment_value

Alignment values:
   5  = Class FORBIDDEN for this race
  -1  = Evil alignment required
   0  = Neutral alignment required
   1  = Good alignment required
   2  = Any alignment allowed
   3  = Good or Neutral alignment
   4  = Neutral or Evil alignment

--------------------------------------------------------------------------------
                    HOW TO ALLOW/FORBID A CLASS FOR A RACE
--------------------------------------------------------------------------------

For global class enable/disable, use lib/creation_availability.cfg:

  creation.class.dragoon.enabled=false

This hides the class from every race's creation menu and rejects direct
selection in both telnet and WebSocket creation. Restart after changes.

For a race-specific class restriction or alignment rule, continue using the
class_table[][] source matrix described below.

================================================================================
                            RACIAL STAT MODIFIERS
================================================================================

Storage: src/core/constant.c (stat_factor[])
Loading: src/world/db.c (update_stat_data())
Configuration: lib/duris.properties (stats.<stat>.<race-name-without-spaces>)

Fields cover Str, Dex, Agi, Con, Pow, Int, Wis, Cha, Kar, and Luk; the Luck
property uses the token luc. Missing factors default to 100. These are racial
scaling factors, not additive creation bonuses. src/magic/affects.c applies the
factor to the character's stat value divided by 100, with affect, item, and
clamping rules. Edit the properties through the normal property workflow rather
than adding hardcoded values to the zero-initialized array.

================================================================================
                               QUICK REFERENCE
================================================================================

To add a new playable race:
  1. Edit src/core/constant.c -> playable_races[]
  2. Add entry: { RACE_XXX, 'key', "faction" }
  3. Ensure class_table[RACE_XXX][] has appropriate class permissions
  4. Recompile

To change class availability:
  - Global enable/disable: edit lib/creation_availability.cfg and restart.
  - Race-specific rules: edit src/core/constant.c -> class_table[][],
    find the race row/class column, set the alignment code, and recompile.
    Codes: 5=forbidden, 2=any, 1=good, -1=evil, 0=neutral,
    3=good/neutral, 4=neutral/evil.

Files involved:
  src/core/defines.h    - RACE_* and CLASS_* constants
  src/core/constant.c   - playable_races[], class_table[], stat_factor[]
  src/core/common.c     - race_names_table[], class_names_table[]
  src/account/nanny.c      - Telnet character creation (uses playable_races[])
  src/net/ws_handlers.c - WebSocket character creation (uses playable_races[])

================================================================================
                              TROUBLESHOOTING
================================================================================

Q: I added a race but it doesn't appear in character creation
A: Check roster membership, its per-race switch, the all-races setting when
   using a restricted race, and the running binary. Add roster entries before
   the sentinel { -1, 0, NULL }.

Q: Players can't select a class that should be available
A: Check the per-class switch, class_table[race][class] (5 is forbidden),
   override settings, alignment handling, and account side admission.

Q: WebSocket client shows different races than telnet
A: Both use the shared roster and availability helpers. Check client handling
   of restricted/restricted_note fields and the running binary. Their alignment
   selection paths differ as described above.

Q: Race name shows wrong in WebSocket client
A: Check race_names_table[] in common.c matches the RACE_* constant
